# 砖了个砖提示

在桌宠任务列表选择“砖了个砖提示”并启动。保持一个标题为“砖了个砖”的游戏窗口打开。任务只读取该窗口画面；鼠标点击和拖动全部由用户完成。

## 使用方式

- 黄色圆圈标出要点击的砖，配对砖保留紫色圆圈；画面不显示文字或编号。提示角色的手指始终对准目标，身体允许在屏幕边缘被裁切。
- 拖动时，黄色圆圈标出要移动的砖，黄色箭头指向拖动终点；配对目标保留紫色圆圈，角色只沿起点到终点示意，不再跳到配对砖。
- 游戏出现多个高亮候选时，按提示点选配对目标。
- 快速推进：主动砖区域明显变化后，配对格确认为空，就直接显示已有计划的下一步，不等待全盘分组。只检查局部空格，不把同类砖抖动、选中高亮或白色闪光当作消除。
- 每次推进只触发一次；下一步的两个区域稳定200毫秒后才重新启用变化检测，避免旧动画连续跳步。已进入多个候选点选状态时保留完整识别。
- 每两秒在画面稳定时完整复核，发现偏差后撤下提示并重新求解。完整识别仍逐格检查稳定性，避免把局部消除闪光分组为新砖。
- 每轮以100毫秒为最小周期，截图与处理耗时计入周期，超过时不再额外等待。完整识别仅复用规范化像素完全相同的砖面比较结果，并检查完整分组可靠性；重新求解后仍重新截图确认。
- 停止任务、隐藏桌宠或提示超过1.8秒未收到确认，都会撤下指引。

## 识别范围与边界

目前支持14×10棋盘：优先通过外框轮廓与规则砖格排列定位，根据实际砖格中心校正装饰边距；没有结构候选时保留橙色边框定位。保留原始轮廓和闭合处理后的轮廓，断开的外框必须额外具备足够多、跨多行多列的规则砖格。已验证冰蓝色和黄色皮肤；最后一对消除后，仅在匹配的外框仍可见时复用已确认的格子位置。每次读取当前画面中的砖面，容许少量像素偏移后比较相似度、动态分组并分配临时编号；运行时不加载图案模板或名称表，新图案无需手动收录。提示只使用行列位置。分组数量为奇数、组内差异过大或组间难以区分时停止并保存诊断，不用偶数约束强行配对。其他棋盘布局、纹理底板和严重遮挡仍有限制。

空格根据当前格子的平坦颜色与边缘连续性识别，不固定底板颜色。纹理底板尚未验证。

规则：相同图案同一行/列且中间只有空格可消；起始砖已经能直接配对时只允许点击消除，不生成拖动，也不允许借一起移动两块同类砖来绕过限制；一次拖动只能沿一个方向移动起点及前方连续砖块，起始砖在终点必须形成配对，否则回弹。每次建议来自完整清盘搜索，不包含自由转向或无消除的中间移动。

## 实现

- `task.py`：纯SDK描述入口与子进程生命周期。
- `recognition.py`：颜色定位与结构定位、当前画面动态分组与不确定性检查。
- `solver.py`：先短暂尝试优先消除内部直接配对的搜索顺序，未找到时在同一个总预算内切回原顺序；有停止检查和8秒/60,000节点上限的纯Python回溯求解。达到上限时显示“搜索未完成”并继续观察，不判定无解、不退出；棋盘变化后重新搜索。
- `controller.py`：只调用窗口枚举和WGC截图，发送`hint`事件；根据布局对应关系消除临时编号变化，保留已有计划和待选配对状态；没有鼠标注入调用。
- 宿主的`PointOverlayWindow`呈现提示，窗口不抢焦点、鼠标穿透。`hint`是协议v1的新增事件，旧任务无需改动。

失败诊断保存在仓库的`artifacts/brick_hint/<时间>/`，包含截图和识别/求解状态。

运行日志在棋盘状态改变时记录“首次求解”“命中预期，复用计划”或“未命中预期，重新求解”，并记录定位、识别和求解耗时。未命中时记录上一步动作及规范化后的预期/实际棋盘（140字节的十六进制序列），用于区分计划偏离与识别变化；静止棋盘不重复刷日志。

日志另记录“快速推进”及“完整复核”的匹配结果，区分快速推断与已确认状态。
